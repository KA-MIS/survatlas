# Contributing to SurvAtlas

Thanks for your interest in SurvAtlas.

## Repository scope

This repository is the **public documentation and project showcase**. The application source is developed in a **separate private repository**. Public contributions here are welcome for documentation, typo fixes, accessibility observations, reproducible test suggestions, and well-scoped engineering discussions. An issue or pull request does not grant access to private source code.

## Before opening an issue

- Check [existing issues](https://github.com/KA-MIS/survatlas/issues) and the [roadmap](ROADMAP.md).
- Explain the problem or proposal, its impact, and how it could be verified.
- For documentation bugs, provide the affected section or link.
- For software behavior reports, include only non-sensitive details and clearly indicate whether you personally reproduced the behavior.

## Pull requests

1. Open an issue first for substantial changes.
2. Keep each pull request focused on one documentation or showcase improvement.
3. Describe what changed, why, and how you verified it.
4. Check Markdown formatting, relative links, and image references.
5. Do not claim that a planned capability is complete without evidence.

Project maintainers review contributions when available; submission does not guarantee acceptance or a response time.

## Safety and privacy

Do not include credentials, tokens, personal information, private code, proprietary datasets, or confidential system details. Avoid posting instructions that could be mistaken for validated medical or emergency advice. Label unverified claims clearly.

## License and ownership

Contributions are subject to the repository's applicable license and GitHub's terms. If no explicit license applies, do not assume that project assets or code are available for unrestricted reuse. For significant third-party materials, obtain permission before submitting them.

## Contact

Use [GitHub Issues](https://github.com/KA-MIS/survatlas/issues) for public project discussions.
